# DSH Desktop v0.5.4 — Tauri 2

> 本版本聚焦**多 agent 白屏根治** + **会话崩溃双修** + **WSL 后端五问题** + **第三方思考强度**，累计修复 20+ 项用户反馈的 BUG。

## ⚠️ 重点 1：多 agent 客户端卡顿/白屏 —— 根治

根因是内核 UI 会话事件流**无上限累积**，多子代理跑一会儿就吃光 WebView2 渲染进程内存导致白屏。

- **治本**：会话事件有界保留（2000 条封顶、按轮次对齐裁剪）+ 会话 `dispose()` 真正释放内存
- **自愈**：白屏后三级恢复梯自动救活（eval reload → 原生 reload → 浏览器进程级重载）
- **熔断**：连重载都救不活时自动升级到内核重启，不再「40 秒一次」无限闪屏

## ⚠️ 重点 2：会话崩溃双修（内存尖峰 + 历史加载失败）

- **打开子代理崩溃**：全量扫描 291 个会话文件逐个 zstd 解压 header 顶爆内存 OOM → 加 header 扫描缓存（文件未变零解码）+ 读上限 256KB 封顶。
- **对话中「本轮运行失败」→「历史加载失败」→ 崩溃**：加载路径缺损坏降级（列表能跳过、加载必炸）→ 改为「加载到最后一个完整帧」优雅降级（header 损坏仍致命、告警保留）。

## ⚠️ 已知限制（内核上游，本期不改）

**自定义多模态模型读不到图片**：内核 `dsh-llm-pi-ai` 对未显式声明 `input` 的自定义模型回落 `DEFAULT_INPUT=["text"]`，视觉模型被误判为纯文本、图片被 `MODEL_DOES_NOT_SUPPORT_IMAGES` 拒绝。这是上游 @deepseek-ai/dsh 的能力缺口（设置页无 input-modalities 字段）。

**用户侧临时绕法**：在 `settings.yaml` 的 `llm-pi-ai` 给该模型手动加一行：

```yaml
llm-pi-ai:
  models:
    - id: 你的模型id
      provider: 你的provider
      input: [text, image]
```

（已向上游反馈：① pi-ai 允许自定义模型声明 input ② 设置页补 input-modalities 字段）

## 🔄 升级说明

1. 完全退出当前 DSH Desktop（托盘右键 → 退出）
2. 下载对应平台安装包并运行
3. 安装器自动检测旧版并装回原目录（**数据不丢失**）
4. 首次启动自动同步全部插件与设置

> macOS 首次打开如提示「已损坏」，右键 app → 打开，或 `xattr -cr "/Applications/DSH Desktop.app"`。
