# DSH Desktop v0.5.1 Release Notes（草稿）

> **⚠️ 预览版 · 不发布**
> 本文件为 v0.5.1 本地打包的 release notes **草稿**。v0.5.1 仅在本地打包验证，
> **不推送 tag、不上传 GitHub Release、不同步 Gitee**。对外最新发布版仍为
> v0.5.0（2026-08-21）。

**一句话**：内核家族随官方 deepseek-harness 1.1rc 整体升级，并根治 v0.5.0
实测暴露的赞助窗、WSL、安装器与「内核被误杀」四类问题。覆盖安装即升级，
用户数据零迁移。

---

## 1. 内核升级：0.1.0-rc.8 → 0.1.1-rc.1（deepseek-harness 1.1rc）

**修了什么**：内置的 DeepSeek Harness 内核家族从 0.1.0-rc.8 平移到官方
1.1rc 对应的 0.1.1-rc.1（`@deepseek-ai/dsh` 及 18 个伴随包，共 19 个依赖
整体对齐官方 release：github.com/deepseek-ai/deepseek-harness 1.1rc）。
官方在该版本中的修复与改进随安装包一并获得，离线可用。

**为什么**：桌面端内核随客户端发版升级（Tauri 架构既定决策），本次跟进
官方 rc 通道迭代。

**内部适配**（用户无感，供排查参考）：

- dsh-file-changes 伴随插件适配内核投影 API v2（`schema` → `stateSchema`、
  `view` → `wire:{viewSchema,view}`）；
- supervisor 的内核版本断言放宽为 `starts_with("0.1.")`——今后 rc 通道内的
  小版本迭代不会再因版本锚点过紧而拒绝启动。

**已知变化（升级注意）**：`billion-context` 插件的「剩余上下文预估值」
（contextPressure 快照优化）在本版内核中失效——1.1rc 的 compaction 实现
移除了该快照键。插件自身有防御守卫，会**优雅降级**：不崩溃、不报错，
仅暂时失去这一层预估值显示，压缩功能本身不受影响。待插件上游适配后
随后续版本恢复。

## 2. 赞助窗根治：无图 / 卡死 / 关不掉一次修完

**修了什么**：赞助窗口（帮助支持项目）此前在部分环境下出现「打开空白
无图」「关闭时整个应用卡死」等问题，本轮根治。

**为什么 / 怎么修**：旧实现依赖运行时落盘 + 本地页面加载，环节多且各有
平台坑。新实现做到**三零依赖**：页面资源编译期内嵌进程序（零 `file://`
页面、零本地端口、零磁盘写入），二维码以 data URI 直接注入，窗口在独立
线程创建，关闭走系统默认销毁路径。顺带规避了 Tauri 上游 #13419（测试
exe manifest 崩溃）在本项目的触发路径。

**升级注意**：无。赞助窗打开与否不影响主功能；此修复只让它「该有图有图、
该关掉关掉」。

## 3. WSL 两项修复

**修了什么**：

1. **插件误判修复（#132）**：WSL 环境下 pnpm 目录结构的插件此前可能被
   误判为「无法解析」而隔离，导致插件消失。现在增加 pnpm store 解析回落
   与真实路径校验；WSL 的 UNC 路径无法验证时**只登记告警、绝不误删**，
   且历史被误隔离的插件会自动恢复（隔离自愈）。
2. **「假开关」根治**：设置里的 WSL 托管开关此前在 Tauri 版呈现为可切换
   状态，但后端尚未实装——切了也没用。现在诚实提示「暂未实装」，不再
   给出会误导的可用假象。

**为什么**：WSL 误删用户插件属于数据安全问题，优先根治；假开关违反
「兼容性不报错」的诚实原则。WSL 完整托管仍在路线图后续，实装后会在此
设置项处直接可用。

## 4. 内核「假死」误杀修复：探活阈值 15s → 60s

**修了什么**：长对话触发上下文压缩（compaction）时，内核事件循环会被
占用 20-30 秒——这期间端口通但 HTTP 无响应，属**正常工作形态**。此前的
15 秒假死阈值会把正在压缩的内核误判为僵尸并杀掉重启，表现为「长会话用
着用着突然重启」。阈值放宽到 60 秒后不再误杀。

**升级注意**：无。真正的内核假死（超 60 秒无响应）仍会被探活并自动拉起，
自愈能力不变。

## 5. 安装器与测试基建（随本版出包）

- **安装器卡死残余根治**：v0.5.0 安装包在个别机器上仍可能「卡在安装中」
  ——NSIS 脚本中 `$R9` 寄存器同时承担两个角色互相覆盖导致空转死循环。
  已修复并重新通过 makensis 全量编译验证。
- **CI 构建修复**：Linux / macOS 云端构建链修复（图标缺失与宠物窗平台
  条件编译），为后续版本产出三平台安装包铺路。
- **测试基建修复**：修复 4 处测试基建缺陷（安装态冒烟脚本死等、shell.pid
  的 winpid 口径、edge-client 沙箱计时器、2 个过时 Electron 用例改锚），
  保证发版闸门本身可信。

| 事项 | 说明 |
|------|------|
| 升级方式 | 覆盖安装即可：自动定位旧目录、静默卸载保数据、装回原位置，用户数据零迁移（与 v0.5.0 升级链一致，详见 upgrade-guide.md） |

| 平台 | 本版仅 Windows x64 NSIS 安装包（本地打包）；Linux / macOS 与便携版随后续版本 |
